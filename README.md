# OCR Benchmark for Intelligent Data Extraction in Import Documentation

IDW, short for Intelligent Document Workflow, is a Python project for generating synthetic import-related documents and evaluating OCR performance on them. It is designed for technical studies, academic benchmarking, portfolio work, and data engineering or document intelligence demonstrations.

All data generated by this repository is synthetic. No real DI, DUIMP, DDI, CTAC, CNPJ, corporate document, fiscal data, or sensitive information is used.

## Project Scope

The project currently covers two main flows:

1. Synthetic dataset generation
2. OCR benchmark evaluation

The dataset generator creates semi-structured fictional documents inspired by import documentation and exports:

- synthetic PDFs
- clean images
- degraded image variants
- ground truth workbook
- benchmark template workbook

The evaluation flow reads a filled benchmark workbook and calculates:

- exact match
- Levenshtein distance
- character error rate
- word error rate
- field-level accuracy
- document-level accuracy
- accuracy by OCR engine
- accuracy by document type
- accuracy by quality variant
- accuracy by field
- average processing time
- average confidence score

## Supported Synthetic Documents

The current generator supports four synthetic document families:

- `DI`
- `DUIMP`
- `DDI`
- `CTAC`

Each document is built with fictional fields such as:

- document number
- issue or registration date
- synthetic CNPJ
- synthetic importer or carrier names
- NCM
- container code
- BL number
- weights and customs values
- terminal, origin, destination, and status fields

## Quality Variants

For each clean document image, the generator creates the following OCR challenge variants:

- `clean`
- `low_resolution`
- `blur`
- `heavy_compression`
- `skew_shadow_noise`

These simulate common OCR issues such as resolution loss, blur, compression artifacts, skew, shadowing, and noise.

## Generate the Dataset

Default command:

```powershell
python src/generate_dataset.py --docs-per-type 20 --output ./dataset
```

Quick smoke test:

```powershell
python src/generate_dataset.py --docs-per-type 2 --output ./dataset_smoke
```

The generator creates:

- `dataset/01_pdfs/`
- `dataset/02_images_clean/`
- `dataset/03_images_degraded/`
- `dataset/04_ground_truth/ground_truth_workbook.xlsx`
- `dataset/05_benchmark/benchmark_template.xlsx`

## Ground Truth Workbook

The generated `ground_truth_workbook.xlsx` contains these sheets:

- `Documents`
- `GroundTruth`
- `Benchmark_Template`

### Documents

One row per document and quality variant, including:

- `document_id`
- `document_type`
- `pdf_path`
- `clean_image_path`
- `degraded_image_path`
- `quality_variant`

### GroundTruth

One row per expected field:

- `document_id`
- `document_type`
- `field_name`
- `expected_value`

### Benchmark_Template

Template to be filled by OCR runs:

- `document_id`
- `document_type`
- `quality_variant`
- `ocr_engine`
- `image_path`
- `field_name`
- `expected_value`
- `extracted_value`
- `confidence_score`
- `processing_time_seconds`

## OCR Layer

The project includes a resilient OCR interface in `src/ocr_extractors.py`:

```python
def run_ocr(image_path: str, engine: str = "mock") -> dict[str, object]:
    ...
```

Current behavior:

- works with `mock` out of the box
- supports optional `tesseract`
- supports optional `easyocr`
- supports optional `paddleocr`
- does not crash when OCR dependencies are missing

Optional OCR dependencies can be installed later as needed.

## Field Extraction

`src/field_parser.py` contains regex and label-based extraction rules for structured fields such as:

- CNPJ
- NCM
- container
- DI, DUIMP, DDI, and CTAC numbers
- date
- BL
- vehicle plates

The parser already returns field names aligned with the generated ground truth, so it can evolve into an automated benchmark runner later.

## Evaluate the Benchmark

After filling `benchmark_template.xlsx`, run:

```powershell
python src/evaluate_benchmark.py --input ./dataset/05_benchmark/benchmark_template.xlsx --output ./outputs
```

Generated outputs:

- `outputs/metrics_output.xlsx`
- `outputs/field_accuracy.csv`
- `outputs/document_accuracy.csv`
- `outputs/ocr_ranking.csv`

## Comparison Logic

Before scoring, values are normalized according to field type. Examples:

- CNPJ removes punctuation
- dates keep only digits
- numeric values normalize decimal separators
- document identifiers remove spaces and punctuation
- text values remove accents, uppercase, and collapse whitespace

This allows comparisons such as:

```text
12.345.678/0001-90
```

and

```text
12345678000190
```

to be treated as equivalent for CNPJ fields.

3. Fill `benchmark_template.xlsx`.
4. Execute the evaluation script.
5. Analyze outputs in Excel, Power BI, or notebooks.
